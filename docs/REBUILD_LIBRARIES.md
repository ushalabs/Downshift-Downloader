# Replacing and rebuilding the libraries

Downshift dynamically links Qt Core, Gui and Widgets under the LGPLv3 option. You may replace these DLLs with compatible modified builds and reverse engineer the application to debug such modifications. There is no library signature or hash enforcement at application startup. Package checksums establish published provenance and do not prohibit replacement.

Each binary release includes a separate dependency-source ZIP at the same release location. It contains the exact SHA-512-verified upstream source archives recorded by the installed vcpkg resources, their licenses, the complete vcpkg source at the pinned baseline (including patches and build scripts), and the application manifest/presets. The Qt source is 6.11.2; the Qt port applies the patches from that included vcpkg baseline. The main release's Git tag provides Downshift's original MIT source and CMake configuration. The binary package's package-manifest.json identifies its source commit and shipped files.

Use Windows x64, Visual Studio 2022/MSVC v143 and the Windows SDK. Extract the included vcpkg ZIP to `.tools/windows/vcpkg` in a clean application source checkout. Place the source archives in its `downloads` folder. For an unmodified rebuild, the pinned baseline can also be cloned by `scripts/Bootstrap.ps1`; configure and build with the README commands. The triplet is x64-windows, shared libraries, Release. Build tools downloaded by vcpkg are build prerequisites and are not shipped runtime libraries.

To modify Qt, extract the Qt archive, apply the `ports/qtbase` patches in their portfile order, and make your edits. Make an overlay copy of that qtbase port and change its SOURCE_PATH to your edited, patched tree (bypassing source download/extraction), retaining its features/options and build/install steps. Configure a separate application build with `-DVCPKG_OVERLAY_PORTS=C:/path/to/overlay` and a separate VCPKG_INSTALLED_DIR. Rebuild Qt and Downshift there; do not reuse the original binary cache for the modified port. Other dependency modifications use the analogous included source/port recipe.

With Downshift closed, replace the app-local Qt DLLs and compatible `platforms/qwindows.dll` from your build. If an ABI or compiler-runtime change prevents drop-in replacement, rebuild Downshift from the release tag against your modified installation. Test with `Downshift.exe --smoke-test`, then run the full source tests. Keep originals separately for rollback.

Qt's complete actual copyright bundle, LGPLv3/GPLv3 texts and third-party notices are under licenses/qtbase/copyright. See [Qt obligations](https://www.qt.io/development/open-source-lgpl-obligations). The source kit and application source should be preserved and provided with further redistribution. Optional video helper executables are fetched directly by the user from upstream and are not included in the Downshift binary archive.
