# Windows portable distribution

## Compressed Windows setup

The current working-source package is version 1.0.0. It includes the verified native-primary YouTube extraction path and the shared `Downloads/Torrents` destination repair. Packaging still rejects stale compiled-source fingerprints and preserves the clean-release gate; local unsigned builds from the user's uncommitted checkout explicitly retain their working-source preview metadata.

`Test-Setup.ps1 -ElevatedProduction` runs the actual administrator-requiring setup under a separate generated Program Files directory. `/ISOLATEDTEST` keeps all integration in private keys/shortcuts, so this tests protected-location installation without replacing the normal application. `-YouTubeTestDriver <driver> -YouTubeReportPath <json>` additionally completes two real public YouTube transfers through the installed Qt dialog, verifies pinned helper hashes and independently checks final audio/video, duration, resolution and decoded frames. Normal browser credentials and history are not used. The report distinguishes this actual elevated production-executable test from the non-elevating fixture, and from an ordinary HKLM integration installation or clean-VM certification.

`scripts/Build-Setup.ps1 -LocalPreview` creates `dist/Downshift-0.4.5-Setup-x64.exe` from the verified Release binaries and matching working-source snapshot. For clean-source builds use `-RequireClean` instead. The portable NSIS 3 compiler can be supplied with `-NsisCompiler`; the local tool directory is the default. The existing portable builder's source fingerprint and clean-checkout gates still apply.

Version 0.4.5 also migrates a recognized older per-user Downshift native-host override to the installed host, since Chrome checks HKCU ahead of HKLM. Its prior value is backed up; a matching old user Desktop shortcut is backed up and updated too. Uninstall restores these only while the installation still owns them and the Windows user matches. Unknown overrides are preserved and reported. Private acceptance uses separate alias keys and a synthetic old shortcut, never normal registration or Desktop files.

The EXE setup uses solid LZMA compression, defaults to `C:\Program Files\Downshift` (64-bit Program Files), requests administrator approval, and installs for all users. It registers Chrome's native host and Windows Apps uninstall information in HKLM and creates common Desktop and Start menu shortcuts. History/settings and downloads remain per-user in their existing writable folders; binaries and video tools live under Program Files. Setup does not launch Downshift or close another running copy. Quit an installed copy before upgrading its files. Uninstall an older per-user AppData setup before moving to this machine edition so its HKCU Chrome registration does not shadow HKLM; its uninstaller preserves user history/downloads.

The setup welcome page prominently credits **UshaLabs**. Its window caption, footer, executable CompanyName and Windows Apps publisher also identify UshaLabs. The original application retains the MIT terms and contributor attribution; dependency licenses remain separate. The final local preview uses the verified video Pause/Resume, window/tray lifetime and editable-filename build. Packaging acceptance includes real direct and segmented video continuation using the automatically installed tools.

EXE setup now automatically downloads and installs the pinned yt-dlp, Deno and LGPL shared FFmpeg tools (about 136 MiB of upstream downloads); Internet access is required for a new installation. No Enable-video action is needed. `scripts/media-tools-lock.json` pins both archive and extracted runtime SHA-256 values. All archives are verified before installed helpers are replaced, extraction is staged, unchanged verified installations are reused without downloading, and setup fails visibly on download/verification errors instead of claiming complete video support. Successful setup removes only matching cached archives. ZIP-only users can still run Enable-video.cmd. The upstream helper binaries are not redistributed in the EXE/ZIP.

The finish page offers to open `Chrome-setup.txt`, a plain text guide with short steps, the exact installed extension folder, and instructions for starting normal/video/torrent downloads and using the tray. Start > Downshift > Chrome setup can reopen it. A copy beside the setup uses the default installation location; custom installations generate their own exact path inside the app folder. Chrome still requires Developer mode > Load unpacked for this unpublished preview. [Chrome's supported Windows external-install mechanism](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions) requires a Chrome Web Store listing and subsequent browser confirmation. No store listing, browser policy injection, profile editing, automatic extension loading or permission acceptance is claimed. Silent and isolated test installs never open the guide or Chrome.

The video bootstrap has a bounded 30-minute installer allowance rather than the previous 10-minute limit, which expired during a slow upstream FFmpeg download. Per-asset web requests have a 15-minute timeout. Existing verified cached archives are reused and all extracted hashes still have to match. `Test-Setup.ps1 -MediaArchiveCache <folder>` can seed immutable archive files into its private installation cache after checking their pinned SHA-256 values. Its report explicitly distinguishes that extraction/install fixture from a fresh upstream network-download test.

Uninstall restores integration only while it is still owned by that installation and removes only the packaged file inventory plus downloaded video files that still match the pinned inventory and installation receipt. Modified helper files and unknown files are preserved. Download/history directories and unknown files are preserved, including files a user placed inside the application directory. Shared Qt libraries remain replaceable. Keep the matching application-source and dependency-source ZIPs beside the setup when archiving or redistributing it. Local working-source previews remain unsigned and marked as previews; creating setup does not publish a release or run remote CI.

For a non-elevated hidden fixture, build with `Build-Setup.ps1 -VerificationSetupPath <private.exe>` and pass that file to `Test-Setup.ps1 -SetupPath <production.exe> -VerificationSetupPath <private.exe> -PackagePath <portable.zip> -VideoTestDriver <downshift_media_tests.exe> -PythonExecutable <python.exe>`. Both NSIS executables use the same payload and script; the private variant uses asInvoker and refuses normal installation. The fixture checks production's administrator manifest, isolated install/reinstall/uninstall, Desktop target/icon/working folder, read-only instruction opening, pinned media tools and actual media transfers. It leaves real Desktop, registration and user state alone. Actual elevated machine-wide installation and clean-VM acceptance are separate, unperformed checks in this environment. `Test-Portable.ps1` checks prior/later shortcut ownership, matching sources, runtime loading and HTTP/torrent transfers.

For installer-only changes, `-InstallerOnly -PreviousMediaReport <json> -PreviousPortableReport <json>` keeps the installer and helper-hash checks but skips media transfers only after matching the application hash to previously verified media/portable evidence. Reports keep current and previous media counts distinct. This mode does not convert an observed media-suite timeout into a pass.

Phase 9 uses the accepted portable-distribution route. Windows 10/11 x64 is required. Extract the complete ZIP to a permanent writable folder; double-click Setup.cmd, then the Desktop Downshift shortcut. The application runs without Visual Studio, CMake, Python, Node or a system Qt install. Microsoft VC143 runtime DLLs, shared Qt/curl/SQLite dependencies and the Windows Qt plugin are app-local. Keep these files beside the executable.

Setup is per-user, requires no administrator rights, registers the restricted Chrome Native Messaging host and creates a Desktop shortcut. Open chrome://extensions, enable Developer mode, Load unpacked, and select the package's extension folder. Chrome Web Store installation is not provided. Existing extension installations require Reload and reloading video pages. Source-development setup remains documented separately in INSTALLATION.md.

Enable-video.cmd optionally fetches the exact upstream yt-dlp, Deno and FFmpeg releases after SHA-256 verification. It needs Internet access and installs helpers in media-tools beside the app; the portable ZIP does not redistribute those executables. Ordinary file downloads run immediately without them. There is no automatic helper update.

Uninstall.cmd restores the saved prior native-host registration and Desktop shortcut only if this package still owns them. It leaves later installations alone and never deletes user downloads or encrypted history. Remove the extension in Chrome; delete the extracted app folder manually afterward. To move an installation, uninstall its integration in the original location first and run Setup in the new one. Local history remains under the Windows user application-data directory across package replacement.

This preview is unsigned; store certification and an auto-updater are not provided. The compressed installer is described above. Keep source and dependency-license bundles with redistribution. See THIRD_PARTY_NOTICES.md and REBUILD_LIBRARIES.md.

## Build and verification

From a verified Release source build:

```powershell
./scripts/Build-Portable.ps1 -RequireClean
./scripts/Test-Portable.ps1 -PackagePath ./build/releases/Downshift-0.4.4-windows-x64.zip -ReportPath ./build/package-test-report.json -TorrentTestDriver ./build/windows-msvc/Release/downshift_torrent_acceptance_tests.exe -PythonExecutable (Get-Command python).Source
```

The build script bundles only the two product executables and release runtime libraries, not tests/debug/developer tools or video helpers. It generates the extension ZIP, package manifest with SHA-256 per file, separate complete dependency-source kit with vcpkg patches/recipes, and SHA256SUMS.txt. Missing source archives are fetched from their recorded upstream location and must match the exact installed SPDX SHA-512. Release publication requires a clean checkout; development packages explicitly report dirty source.

The test extracts to a path containing spaces, verifies every manifest hash, requires app-local runtimes/licenses, checks extension identity/version, repeats setup, validates host path/origin and shortcut, then opens the actual packaged Qt window with PATH restricted to Windows system directories. It verifies the loaded Qt/curl/SQLite/VC runtime modules came from that extracted package. Smoke mode uses an isolated database and leaves the normal pipe/history untouched. Uninstall must restore prior registration/shortcut, retain the app files, and preserve a different later installation. Both successful and failed tests restore the original registry state and clean only their validated temporary directory.

Local acceptance: 13 checks passed using built-in Windows PowerShell 5.1; the package loaded its own runtime libraries. This is the development Windows 11 machine with a sanitized PATH, not a separately provisioned clean Windows VM. Debug desktop/startup regression checks also passed after the prominent Qt license notice was added. Final release evidence and remote Windows CI are recorded separately in DEVELOPMENT_PROGRESS.md.

## T4 local previews and source identity

When Git is intentionally left to the user, use `Build-Portable.ps1 -LocalPreview -OutputDirectory ./build/t4-local-preview`. The package is marked LOCAL-PREVIEW and nondistributable; `-RequireClean` continues to reject a dirty checkout even when LocalPreview is supplied. Both clean and preview packages include an application-source ZIP built from the actual tracked/nonignored source bytes, plus its hash and per-file source inventory. Compiled input fingerprints must match that source inventory. Private data/build/dependency work folders are excluded.

The extracted verification now checks matching application source, Rasterbar/OpenSSL runtime loading and notices, and runs the mixed eight-torrent/HTTP/HTTPS native Qt fixture using a verification-only driver beside the extracted DLLs. PNG/JPEG/WebP decoding and the native TLS backend are exercised there. Installer tests use only `org.ushalabs.downshift.packaging-test`; ordinary Setup/Uninstall retain their original namespace. Test fixtures and the test driver are not distributed. CI supplies the driver and Python path explicitly. Remote CI and a clean published artifact remain separate evidence from an uncommitted local preview.


To build a preview without replacing a currently running development EXE, configure `-DDOWNSHIFT_PRODUCT_OUTPUT_DIRECTORY=<absolute-preview-directory>`. The product EXEs/plugins/fingerprint are emitted there under Release/Debug while test drivers remain in the usual build folders. Pass that Release directory with `Build-Setup.ps1 -BinaryDirectory <path> -LocalPreview`. The same fingerprint gates apply; this does not relabel an older executable as current. The current media repair uses build/media-package/Release and preserves the normal running application.
